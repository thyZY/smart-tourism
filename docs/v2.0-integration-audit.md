- 当前 UI 主开发线：`feat/v1.9-poi-name-picker-20261015`，PR #11，CI #38704600885 通过。
- 另一条独立开发线：`feat/poi-tourism-metadata-20261008`，PR #3，仍为 Draft。
- 这两条开发线**没有被合并**；`main` 也未被改动。以下是基于仓库源码、PR 和接口的静态审计，**不是**浏览器/PostGIS/DeepSeek/Valhalla 端到端测试。

## 已确认存在的接口与边界差异

| 域 | 当前 v1.9 线 | 旧深度功能线 | 集成决策 |
|---|---|---|---|
| AI 行程入口 | `POST /api/ai/itinerary/generate`，单日、按 DB ID 排序、可排除景点 | `POST /api/ai/itinerary`，道路时间矩阵、预算/出发时间等约束 | **禁止直接用同名逻辑互相替换**；先定义统一 schema/适配层 |
| 行程恢复 | `POST /api/ai/itinerary/restore` 重新查 DB | 深度线有再规划、锁定、替换、对话确认等 API | 明确区分恢复、修改和重新规划 |
| 路网来源 | 可选本机 Valhalla 服务；否则明确直线预览 | 双点/多站三模式路线、时间矩阵、入口审核元数据 | 对“验证道路”统一状态含义，失败不得改称导航 |
| 景点信息 | 目前详情没有可靠开放时间/评分来源 | 可选旅游语义迁移与草稿描述、人工审核入口 | 语义草稿不得被升级为事实；数据库迁移须备份、人工执行 |
| UI | 三栏聚合地图、AI 工作台、保存导出、筛选和排除 | AI 对话、锁定/替换、多模式比较、道路入口审核 | 必须逐项交互迁移、截图验收，不能直接覆盖整个 App.vue |
| CI | 代码模拟测试及 Vue build | 各阶段模拟测试与独立 Windows 验收程序 | 合并前建立联合测试并执行实际 PostGIS/路网验收 |

## 需要优先处理的整合风险

1. **API schema 冲突**：两种行程生成请求格式、响应字段及失败状态不同。先冻结兼容字段，新增适配器，再逐一迁移前端调用。
2. **历史快照**：v1.9 浏览器本地存储仅保留已选 ID/交通方式；升级后不能假设已保存预算、推荐理由、模型状态。旧快照恢复必须按当前数据库重新查询。
3. **来源真实性**：数据库 POI 点、未经审核的旅游描述、已审核入口和 Valhalla 道路不是相同可信级别。显示来源、回退状态和缺失信息。
4. **前端状态**：切换地图、重新规划、确认预览、锁定/移除、失败回滚、异步请求过期保护必须共存；不能用旧结果覆盖用户的新操作。
5. **数据结构迁移**：入口数据和旅游元数据需要独立 dry-run、备份和明确的人工批准；本轮不执行迁移。

## 推荐 v2.0 实施顺序

1. **Gate A（本 PR）**：锁定当前 OpenAPI 契约、重复路由检查、对两套功能边界作书面审计。无运行时合并。
2. **Gate B**：编写统一行程请求/响应契约及跨版本适配器测试；保持现有客户端可用，不引入数据库修改。
3. **Gate C**：先移植独立的多站道路服务（只接真实 DB ID；不可达明确报错），再对齐三模式缓存与入口审核来源。
4. **Gate D**：接入确认式 AI 多轮修改，保证预览/用户确认/回滚；迁移历史快照与导出兼容性。
5. **Gate E**：Windows 上完成真实 PostGIS、Valhalla、DeepSeek（主动授权付费请求）、1600/1280/390 px 浏览器截图及 CSV/GeoJSON/PDF/QGIS 实测，再讨论主分支合并。

**不可宣称**：已合并两条分支、已有实时导航/真实景区开放时间、AI 推荐准确率已验证、CI 通过等于本地环境验收。
